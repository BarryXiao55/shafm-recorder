# Changelog

本项目所有版本均保持「零二次损失」录制原则。完整的技术细节、故障排查与验收记录见 `docs/OPERATION_MANUAL.md`。

## v3.1.12（2026-11-16）· 当前发布版

**问题**：`FM990_20261116_062951_0000.mp3` 与 `FM990_20261116_090008_0000.mp3` 是两个 0 字节文件，UI 标记「疑似损坏」。

**根因**：直播源在任务结束前短暂中断（日志中的 TLS `-138` 错误与 code 0 退出），程序按设计重连；重连后的 ffmpeg 先创建输出文件再拉流，若直到任务到点都没有完整音频帧落盘，文件就一直保持 0 字节。segment 封装器打印「正在写入」只代表文件被打开，不等于有数据。健康检查按 `size < 8` 判定，于是显示「疑似损坏」。

**修复（三项全部实施）**

1. **收尾清理**：新增 `lib/segment-guard.js`，任务结束时只清理**本次任务自己创建**、且小于 8 字节的片段；拒绝路径穿越，不扫描目录、不碰用户其它文件。文件刚 `end()` 句柄未关时延时重试一次；清理结果写入 `job.emptySegments` 并记入日志。
2. **尾部不重连**：ffmpeg 退出时剩余 ≤ 15 秒不再拉起新进程，直接以新终态 `interrupted`（源中断）结束；`interrupted` 是终态（可删除任务记录、不算在途），但**保留每日重复排期**——主体节目已经录到，只丢尾部。内置 ICY 引擎的尾部断流走同样规则。不限时长任务不受影响，仍会重连。
3. **首帧超时**：重连后创建的片段启动 12 秒首帧守卫，`_tick()` 以文件真实大小判断；无数据则放弃该片段并按源中断结束，有首帧立即解除守卫。ffmpeg 与内置引擎共用同一套逻辑。

**兼容与呈现**：`interrupted` 在任务徽标显示为「源中断」，任务行显示「已清理空片段 N 个」；0 字节历史文件由 `storage.inspectAudio` 标记为「空片段（源中断）」，UI 不再写「疑似损坏」。新增纯函数 `decideFfmpegExit()` 覆盖三条退出分支。

**验收**：新增 `test/empty-segment.js`（9 组 61 项）；`npm test` 八套全过；独立端口 8803 + 本地假流 8804 的真实服务端 E2E 验证「尾部断流 → interrupted → 0 字节文件被清理 → 日志记录完整」；本机 8787 服务、`runtime.json`、`config.json` 与全部录音未改动。

## v3.1.11（2026-11-16）

**问题**：回听录音时删除另一个文件（或列表自动刷新）后，正在播放的声音被打断、进度归零。

**根因**：`renderFiles()` 用 `innerHTML` 整体重建 `#fileList`，而回听用的 `<audio controls>` 就嵌在每条文件行里。DOM 元素被销毁重建后，浏览器会重新创建媒体元素、清空 `currentTime` 并停止播放。删除确认后的乐观刷新、800 ms 补刷、每秒轮询都会触发这条路径。

**修复**

- 回听播放器改为**列表外的单例** `<audio id="playbackAudio">`，放在 `#fileList` 之后；行内只保留「▶ 回听 / ■ 停止」普通按钮，`renderFiles()` 重建列表时播放器元素本身完全不被触碰，`paused` 与 `currentTime` 原样保留。
- 删除其它文件、手动点「刷新」、每秒状态轮询都只同步按钮文字 / 显隐；只有**正在回听的那个文件**确实从列表消失时才自动停止并给出提示（含外部删除、清理测试文件）。
- 回听纳入全局单例排他：开始回听会停掉任务监听与短/长试听，开始监听或试听也会停掉回听，同一时刻只有一路声音。
- 播放器被浏览器拒绝自动播放时保留选中态并提示用户点播放键；点活动行按钮再点一次即停止。

**验收**：新增 `test/playback-chain.js`（12 组 44 项，含「列表 innerHTML 重建后 `currentTime` 保持、无额外 load/pause」「删 B 不打断 A」「轮询不打断」「删 A 自动停」与双向排他）；`npm test` 七套全过。前端静态文件改动，Ctrl+F5 刷新即生效，无需重启服务、不动任何录音/节目单。

## v3.1.10（2026-11-15）

**问题**：向「定时节目单」添加不同电台的录制任务后，录音文件仍统一使用 `FM990_*.mp3`，没有按约定跟随各自频率。

**根因**：`validatePlan()` 完全信任前端传来的 `filePrefix`，服务端不做电台反查；`planJobConfig()` 在 `filePrefix` 为空时无条件回退到全局 `config.filePrefix`（本机正是 FM990）。只有「EPG → 加入节目单」这一条入口会显式带上电台前缀，其余入口都会塌陷。

| 入口 | v3.1.9 结果 | v3.1.10 结果 |
|---|---|---|
| EPG 一键加入（本来正确） | FM1057 / FM909 | FM1057 / FM909 |
| 表单选电台，但前缀框残留上一台的 FM990 | **FM990** | 自动按所选电台校正 |
| 编辑旧计划时换台 | **沿用旧前缀** | 打开表单即回填新电台前缀 |
| 只填流地址、未选电台 | **FM990** | 按流地址反查电台（含 backup 源）→ 频率前缀，并补 `stationId` |
| 快捷模板（不带电台） | **FM990** | 带上当前选中的电台与频率前缀；确实无法识别才沿用全局并提示 |
| `runtime.json` 里遗留的旧错值 | **FM990** | 触发录制时按电台现算一次，磁盘数据不改也能录对 |

**修复**

- 新增 `public/plan-prefix.js`（零依赖 UMD 纯函数）：频率推导、URL 归一化反查、非法字符清理、统一决策 `decide()` / `normalizePlan()`；浏览器通过 `<script>` 加载，Node 端 `require` 同一份文件，**前后端规则完全一致**。
- 服务端 `/api/plans/add`、`/api/plans/update`、`/api/epg/to-plan` 保存前统一校正并写日志；`plansPayload()` 只读派生 `effectivePrefix` / `prefixMode` / `prefixFixed` 供列表显示「实际落盘前缀」「自动 · 按频率 / 自定义 / 沿用全局」「原存 FM990，已按电台自动修正」。
- `scheduler.planJobConfig()` 与 `JobManager.firePlan()` 传入电台库，在**触发时刻**再算一次前缀，兜住存量旧数据。
- 前端「定时节目单」表单：前缀输入框改为自动跟随（只读）；新增「自定义前缀（不跟随频率）」勾选，这是唯一允许不按频率的情况；选择电台 / 改流地址 / 取消编辑都会立刻刷新前缀与说明行；电台库重绘时不再清空正在编辑的电台选择。
- **数据保护**：全程只新增字段与只读派生，不调用任何删除接口、不重写已有节目单、不动录音文件。E2E 在独立端口 8802 的临时副本里跑，本地 `runtime.json` 字节前后一致，本机 8787 服务全程在线。

**验收**

- 新增 `test/plan-prefix.js`：19 组 74 项断言（纯函数、保存链路、触发兜底、真实 `app.js` 的 DOM 表单联动、快捷模板）；`npm test` 六套全过。
- 独立端口 8802 E2E：`PLAN_PREFIX_E2E=PASS · 17 项`，含「模拟 v3.1.9 旧格式节目单 → 重启 → 立即试跑 → 录成 FM909」。
- 发布包独立端口烟雾测试见 `release/RELEASE_NOTES.md`。

## v3.1.9（2026-11-15）

**长时间试听**

- 「信号源 · 上海 FM 电台库」新增 **10 / 30 / 60 分钟长试听**：下拉选时长 →「开始长试听」→ 实时显示「共 X 分钟 · 剩余 HH:MM:SS」→ 到时自动停止，也可随时「停止试听」。
- 10 秒试听与长试听共用同一个临时播放器，与任务行的「监听」**双向排他**；切换电台不会打断正在播放的声音。
- 结束时间按**墙钟**判定并每秒校准，后台标签页被节流 / 系统休眠后也不会超时长放；直播流断流自动重连（最多 5 次、间隔 3 秒），反复失败才提示并停止。
- 新增 `test/preview-chain.js`：10 组 55 项断言，覆盖三档时长、倒计时、墙钟到时、双向排他、断流重连、音量与播放失败。

**FFmpeg 下载 / 安装 / 路径回写**

- 新增 `tools/install-ffmpeg.js`（Node 零依赖）与 `tools/install-ffmpeg.bat`（双击入口）：自动选源 → 下载 → SHA256 校验 → 解压 → 复制三个 exe → 回写安装目录 → 通知服务重新检测 → `-version` 验证。
- 下载源：BtbN GitHub 最新 win64 lgpl/gpl（GitHub API 取最新 asset + digest）、gyan.dev essentials 备用；支持 `--source` 镜像/本地 zip、`--from` 离线目录、`--winget` 通道。
- 安装目录自动写入 `config.json`（`ffmpegHome` / `ffmpegPath` / `ffplayPath`，保留其它字段并备份）、`bin/ffmpeg-location.json`、`bin/ffmpeg-env.bat`；`config.example.json` 只补空字段，源码与文档不写本机绝对路径。
- `server.js` 的 `findExe()` 新增 `ffmpegHome` 与 `ffmpeg-location.json` 两类候选；`tools/record_fm990.bat` 运行时 `call bin/ffmpeg-env.bat`；安装完 `POST /api/detect` 让运行中的服务免重启生效。
- 默认不覆盖已有 exe；`--update` 把旧 exe **移动备份**到 `bin/_backup-<时间戳>/`（不删除），安装失败自动回滚；临时 zip / 解压目录只清理本次生成物。
- `bin/README.md` 重写为完整下载说明（源、版本、校验、手动三步、路径回写表、升级回退、故障排查、许可证）；新增 `test/ffmpeg-installer.js`（39 项断言，全程在临时 `--root` 里跑，不触碰本机 exe / 配置）。
